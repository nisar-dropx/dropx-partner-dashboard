# Invoice-based final P&L

Fin owns the user workflow at `/finance/final-pnl`; the existing `/finance/profitability` keeps its MG, volume, payout and overhead calculations and is labelled Live provisional P&L.

The company-scoped connection uses `FIN_PNL_API_KEY` in Vercel production and Finance-worker secrets. Fin's service-role credential remains inside the existing Fin server. The worker can read only the bounded, fixed-company monthly source endpoint, not arbitrary Supabase tables. User reads require `finance_pnl` access and full-company location scope. Edits/additions require the corresponding permission; preview roles remain read-only.

The final view joins invoice documents retained by Finance-worker with server-generated final expense and recovery evidence. Invoice service month controls income, and XPT rollup follows station parent relationships and portal aliases. GST is excluded. Invoice chargebacks are expenses; the loss register is not an additional expense.

Final workforce/helper costs use latest publication revisions, before recovery deductions. Employee costs use approved payroll net earnings plus statutory/other deductions and employer contributions. Operating costs reuse the existing CPS transaction deduplication and expense-period logic, including contract rent. Estimated shipment payout and configurable CPS inputs are excluded. Payroll-labelled transaction groups are held for review to avoid duplicate payroll expense. The view clearly identifies incomplete coverage and remains open for final cost adjustments.

NL/NNL incident month is an informational reference. The invoice service/billing month recognizes its chargeback expense; a confirmed salary recovery belongs to the payroll month, even when paid the following month. Deferred deductions affect the later payroll month, without reopening the incident month. Dispute outcome, scheduled payroll month and confirmed posting date are separate. Allocation plans alone never create P&L income. Source payroll links are checked before recognizing a recovery. Where the Ops NL register does not provide a posting link, Finance can explicitly confirm a deduction/receipt with an evidence reference; this is recorded as a manual confirmation. Finance schedules do not themselves change payroll. Later source refreshes update payroll evidence in the relevant payroll month.

Manual additions, edits, reallocation, deletion, restoration and recovery schedules live in Finance-worker D1 with revision checks and immutable audit history. Synchronization preserves those corrections. No Tally records or bank payments are modified by this feature.

Validation: `pnpm run test:finance-final-pnl`, existing Finance regression tests, full prebuild and Next build. Finance-worker tests exercise invoice totals, GST, chargebacks, station mapping, authentication, stale edits, audit integrity, deletion/restore, schedules and payroll-month recovery. Test records are isolated from production.


The opening view is a regional summary inspired by the Kerala P&L reference (latest supplied tab: Aug-26), with independent multi-select region, state, model, cluster manager and station filters. Groups expand to station comparison and income/expense heads, which expand again into source entries. Joint manager responsibility is grouped once, avoiding duplicated station totals. XPTs inherit base-station reporting dimensions. Invoice data is sourced from the worker, not copied from the reference sheet.

Manager share is a separate expense. The loader uses effective People responsibility assignments, salary cards and CPS allocation policies. Salary accruals are labelled until published/approved payroll is available. Final payroll replaces accrued cost on covered days, and the transferred amount is removed from the original payroll location. Allocation is calculated over the full responsibility set before filters, preserving every paise. A manager cost moved into stations is not also charged to HO. Source identities remain stable when accrual becomes final payroll so corrections do not create duplicate lines. Missing salary or assignments is a visible coverage gap. Finance schedules still do not change employee payroll.
